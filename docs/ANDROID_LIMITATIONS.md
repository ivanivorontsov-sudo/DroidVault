# Ограничения Android и модель угроз

## Почему APK можно скопировать, а данные — не всегда

Android изолирует внутренние каталоги приложений. Данные в приватном внутреннем хранилище предназначены только для самого приложения; другие приложения не могут читать их обычным способом. Современные версии Android дополнительно ограничивают доступ к чужим app-specific каталогам.

Официальная документация:
- [Access app-specific files](https://developer.android.com/training/data-storage/app-specific)
- [Data and file storage overview](https://developer.android.com/training/data-storage)

Поэтому no-root MVP копирует APK через pm path и adb pull, но не заявляет о копировании приватных данных.

## Что может потеряться при переносе

Даже если APK установился, приложение может потребовать повторный вход. Могут не перенестись:
- приватные базы данных и настройки;
- данные, зашифрованные ключами Android Keystore;
- токены и ключи, привязанные к устройству;
- лицензии, DRM-контент и игровые данные на сервере;
- данные, которые приложение исключило из системного backup.

## Возможные пути переноса данных

1. Встроенный экспорт/импорт конкретного приложения.
2. Штатный перенос Android или облачная резервная копия производителя.
3. Экспорт пользовательских документов и медиа через системный файловый выбор.
4. Root-режим — только для устройств, где пользователь осознанно принимает риск.

## Root не означает универсальное восстановление

Копирование /data/user/0/package может быть недостаточно. Для корректного восстановления могут иметь значение UID/GID, SELinux-контексты, права, версии Android, подпись APK, системные компоненты и ключи Keystore. Ошибка может привести к сбоям приложения или потере данных.

DroidVault не должен автоматически менять системные разделы, снимать блокировки, получать root или запускать команды разрушительного характера.

## Принципы безопасности проекта

- Явно показывать, какие данные реально попали в копию.
- Проверять SHA-256 перед установкой.
- Не передавать данные в сеть.
- Не сохранять пароли, PIN-коды и токены.
- Не выполнять команды из манифеста как shell-код.
- Не удалять исходные приложения и файлы в процессе резервирования.
