# Архитектура DroidVault

## Текущий MVP

Сейчас DroidVault — desktop CLI на Python, который управляет ADB:
- adb.py: обнаружение ADB, устройств, пакетов и путей APK;
- cli.py: команды backup/list/devices/verify/restore;
- manifest.json: описание набора APK, метаданные и контрольные суммы.

## Структура копии

Одна папка на package name. Первый APK из pm path записывается как base.apk, остальные — как split_XX.apk. Порядок сохраняется, поскольку adb install-multiple устанавливает комплект split APK.

## Следующие компоненты

### Desktop GUI
План: Python GUI с выбором устройства, списком приложений, просмотром содержимого копии и мастером восстановления. GUI будет использовать тот же слой ADB, а не дублировать команды.

### Android companion
План: Kotlin + Jetpack Compose. Приложение-компаньон сможет управлять собственными экспортируемыми данными и запускать штатные сценарии переноса. Оно не сможет читать приватные данные произвольных приложений только потому, что установлено на телефон.

### Шифрование
План: контейнер с AEAD (например, AES-256-GCM через проверенную библиотеку), KDF с солью и параметрами в заголовке. Пароль не должен попадать в аргументы процесса, логи или манифест. До реализации шифрование не заявляется как доступная функция.

### Root backend
Отдельный backend с явным подтверждением пользователя, предварительной проверкой свободного места и возможностью отмены. Никакого автоматического root и никаких обещаний универсального восстановления.

## Инварианты

1. Исходные приложения не удаляются при backup.
2. Проверка хешей обязательна перед restore.
3. Неизвестные версии формата отклоняются.
4. Путь файла берётся из проверенного манифеста и ограничивается папкой копии.
5. Отсутствие приватных данных явно отображается пользователю.
